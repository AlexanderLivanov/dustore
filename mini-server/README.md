# MINI Server (MINI ID)

Центральный сервер мессенджера MINI: учётки с глобальными @никами,
каталог публичных ключей и релей, разносящий зашифрованные конверты
между Яндекс.Дисками пользователей.

Клиент в whitelist-сети **не может** обратиться к этому серверу напрямую —
весь обмен клиент↔сервер идёт через файлы на Диске. Сервер живёт там,
где есть открытый интернет.

## Требования

**Node.js ≥ 22.5** — используется встроенный `node:sqlite`, поэтому
для базы данных нет нативных зависимостей. Единственный npm-пакет —
express.

Проверьте версию: `node --version`. Если меньше 22.5 (частый случай —
на сервере стоит Node 18/20 LTS), обновитесь через nvm:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc          # или переоткройте терминал
nvm install 22
nvm use 22
node --version            # v22.x
```

Node 22 — текущий LTS (поддержка до 2027), не бета. Обновление
безопасно для этого проекта.

<details>
<summary>Если обновить Node нельзя (общий сервер и т.п.)</summary>

`db.js` содержит адаптер, который на старом Node автоматически
переключается на пакет `better-sqlite3`. Установите его:

```bash
npm install better-sqlite3
```

Для сборки better-sqlite3 нужны `build-essential` и `python3`
(на Ubuntu: `sudo apt install build-essential python3`). Если система
найдёт готовый бинарник для вашей платформы — компиляция не понадобится.
</details>

## Настройка

1. Создайте OAuth-приложение на https://oauth.yandex.ru:
   - Redirect URI: `https://ваш-домен/auth/callback`
   - Доступы: `login:info`, доступ к Яндекс.Диску
     (для продакшена рекомендуем ограниченный `cloud_api:disk.app_folder` —
     см. «Безопасность»).
2. `cp config.example.json config.json` и заполните CLIENT_ID,
   CLIENT_SECRET, BASE_URL.
3. `npm install`

## Запуск

```bash
npm start         # сайт MINI ID (вход, профиль, ник) — порт 3000
npm run relay     # релей-воркер (в отдельном процессе)
npm test          # тесты релея на in-memory моке Диска
```

## Протокол обмена (через Диск пользователя)

Всё лежит в `MINI/` на Диске каждого пользователя:

| Путь | Кто пишет | Что это |
|---|---|---|
| `outgoing/msg__<ник>__<uuid>.json` | клиент | зашифрованный конверт получателю |
| `outgoing/keyreq__<ник>.json` | клиент | запрос публичного ключа |
| `incoming/msg__<ник>__<uuid>.json` | релей | входящий конверт (ник = отправитель) |
| `incoming/key__<ник>.json` | релей | ответ на keyreq (`publicKey` или `error: not_found`) |
| `keys/public.json` | клиент | свой публичный ECDH-ключ (JWK); релей синкает в БД |

Поток первого сообщения:

```
Алекс                              РЕЛЕЙ                        Вася
outgoing/keyreq__vasya.json  ──►  ник в БД? ──► incoming/key__vasya.json (Алексу)
[ECDH(наш priv, ключ Васи) → AES-GCM → конверт]
outgoing/msg__vasya__uuid    ──►  sender == владелец Диска?
                                  получатель существует?  ──►  incoming/msg__alex__uuid (Васе)
```

## Публичный API

- `GET /api/users/<ник>/key` → `{ username, publicKey }` — каталог ключей
  (доступен только из открытого интернета; клиент в whitelist-режиме
  получает ключи через keyreq).
- `GET /api/health`

## Гарантии релея

- **Анти-спуфинг**: `sender` внутри конверта обязан совпадать с ником
  владельца Диска, с которого файл взят. Иначе файл отбрасывается.
- **Zero-knowledge**: сервер переносит конверты как есть; payload
  зашифрован ключами устройств, расшифровать его сервер не может.
- **Идемпотентность**: `msg_id` фиксируется в таблице `processed`
  **до** удаления исходника — падение между upload и delete не
  порождает дубликат при повторном прогоне.
- Лимит размера конверта — 256 КБ (config: MAX_ENVELOPE_BYTES).

## Безопасность: что доделать до продакшена

1. **Scope `cloud_api:disk.app_folder`** вместо полного доступа к Диску —
   сервер увидит только папку приложения (`app:/`), а не весь Диск
   пользователя. Клиент-мессенджер должен использовать **то же**
   OAuth-приложение и пути `app:/...`.
2. Токены в БД хранить шифрованными (ключ — в env/KMS).
3. Rate limiting на relay и HTTP.
4. Уведомление отправителю о недоставке (сейчас файл получателю-призраку
   просто удаляется с записью в лог).
