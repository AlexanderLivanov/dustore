# Dustore — памятка для Claude Code

Полный путеводитель по проекту и справочник «каждый файл — зачем» лежит в `docs/DEVELOPER_GUIDE.md`. Читай его раздел, когда задача касается незнакомой части; целиком каждый раз читать не нужно.

## Как со мной работать
- Отвечай по-русски, коротко, сначала вывод. Для нового для меня приёма сначала объясни идею, потом код.
- Код — минимальный и прямой, без лишних абстракций и «на вырост».
- **Ничего лишнего не трогай**: правь только то, что просили. Заметил соседнюю проблему — скажи об этом, не чини молча.
- Не выводи значения секретов (пароли, ключи, токены) ни в ответ, ни в коммит.
- Не пушь в `main` и не создавай PR сам. Работай в ветке; PR создаю я.
- Репозиторий публичный: подробности уязвимостей в коммиты и файлы репозитория не пиши — скажи мне в ответе.

## Что это
Dustore — платформа инди-игр: каталог, консоль разработчика, джемы, L4T (поиск команды), лента Fid, чаты, магазин ассетов, GDDB, мобильная PWA (`/m/`).

## Стек (намеренно простой)
- PHP 8.2+ **без фреймворка**, БД через PDO, MySQL. Apache + `.htaccess` (красивые адреса).
- Фронтенд — чистые JS и CSS, **без сборщика**.
- Node.js только для фоновых вещей: `pwa/push-worker.js`, `mini-server/`.
- S3-хранилище для билдов и картинок; платежи — ЮKassa, Robokassa.
- Локально: Windows + XAMPP, проект в `C:\xampp\htdocs`.

## Как устроено
- Страница = один `.php` (логика и HTML вместе). Подключает `swad/config.php`, шапку `swad/static/elements/header.php`, подвал `footer.php`. Новый адрес `/имя` работает сам; адреса с параметром — правило в корневом `.htaccess`.
- Эндпоинты (JSON/редирект) лежат в `swad/controllers/`, `*/api/`, `api/`. Образец — `swad/controllers/jams/save_vote.php`.
- Базы: `dustore` (основная), `desl4t` (L4T), `gddb`. Схемы-дампа в репозитории нет.
- Новые таблицы — миграцией `migrations/NNNN_*.sql` (+ `php tools/migrate.php`) или самоустановкой `ensure_*_table()` с `CREATE TABLE IF NOT EXISTS`. Идемпотентно, без удаления/переименования столбцов.
- Секреты — только `swad/pass.php` (в `.gitignore`), `.env`, переменные окружения.

## Правила для любого изменения
1. Каждый эндпоинт проверяет **права на конкретный объект** (владелец студии, организатор джема), а не только «залогинен».
2. Всё, что пишет, защищено CSRF: `csrf_token()` на странице → заголовок `X-CSRF-Token` → `csrf_valid()` на сервере.
3. SQL — только `prepare` + `execute` с параметрами. Вывод в HTML — через `htmlspecialchars`/`h()`.
4. `header()`, `setcookie()`, `session_start()` — до любого вывода, иначе «headers already sent».
5. Время сайта — Москва (`APP_TZ`); при расчёте интервалов сверяй пояс поля.
6. Стили: темы (`moonlight`, `madness`) — отдельными блоками `body.moonlight-theme …`. Новое должно работать во всех темах и на телефоне. Силу 3D-эффекта крутят только переменные в `float3d.css`.
7. Мобильная версия `/m/` — отдельная кодовая база; правка десктопа её не меняет.
8. При правке `sw.js` меняй версию кэша.
9. Большие файлы (`index.php`, `game.php`, `explore.php`) правь точечно, после правки проверь две темы и мобильную ширину.
10. Файлы `*_old`, `.bak`, дубли не правь и не подключай.

## Джемы
Итоги и награды — один источник: `swad/controllers/jams/jam_awards.php` (`reveal_at` по Москве, `sprint_id`, награды). Фазы — `phase_lib.php`, голосование — `jams/vote.php`.

## Прод
На проде лежат загруженные файлы и локальные правки, которых нет в git. Не предлагай слепой `git pull` на проде и не перезаписывай там конфиги и секреты.

## Git
Ветка → PR в `main`. Сообщения коммитов — по-русски, коротко: что и зачем. Не коммить логи, дампы БД, `.idea/`, загрузки пользователей, `*.bak`.
