Jams API

Публичная статистика игровых джемов Dustore: участники, команды, билды, динамика загрузок, движки, жанры и география. Только агрегаты — без персональных данных. Ключ не нужен.

GEThttps://dustore.ru/jams/api

Быстрый старт

# все джемы
curl -s 'https://dustore.ru/jams/api' | jq

# полная статистика конкретного джема
curl -s 'https://dustore.ru/jams/api?id=12' | jq

# одна секция
curl -s 'https://dustore.ru/jams/api?id=12&section=builds' | jq
const r = await fetch('https://dustore.ru/jams/api?id=12&section=overview');
const { overview } = await r.json();
console.log(`${overview.builds} билдов от ${overview.devs_finished} разработчиков`);

Общие правила

Что Как
Метод Только GET. Остальное — 405.
Формат application/json; charset=utf-8, UTF-8 без экранирования кириллицы.
Авторизация Не требуется. Эндпоинт публичный.
CORS Access-Control-Allow-Origin: * — можно дёргать прямо из браузера.
Кэш 60 секунд на сервере. Заголовок X-Cache: HIT|MISS, плюс Cache-Control: public, max-age=60.
Время Все даты — Europe/Moscow. generated_at в ISO 8601.
Размеры Всегда в байтах, целым числом. Форматирование — на стороне клиента.
Стабильность полей Новые поля могут добавляться без предупреждения — не полагайтесь на точный состав объекта. Существующие поля не переименовываются в рамках v1.

Статистика джема

GET/jams/api?id=<sprint_id>
Параметр Тип Описание
id int, обязательный ID джема (sprints.id). Синоним — sprint_id.
section string Вернуть одну секцию вместо всех: overview, builds, timeline, teams, tech, geo, activity, leaderboard. По умолчанию — всё.

Ответ всегда содержит success, generated_at и объект sprint с датами этапов, а дальше — запрошенные секции.

{
  "success": true,
  "generated_at": "2026-08-17T14:20:03+03:00",
  "sprint": {
    "id": 12,
    "title": "К.О.Н.Т.У.Р.",
    "status": "ongoing",
    "jam_start": "2026-07-05 12:01:00",
    "jam_end": "2026-08-10 23:59:00",
    "voting_start": "2026-08-14 12:01:00",
    "voting_end": "2026-09-14 12:00:00"
  },
  "overview": { "…" : "…" }
}

section=overview

Поле Тип Значение
participants int Зарегистрировалось на джем.
teams_created int Команд создано, включая пустые и из одного человека.
projects int Проектов заведено на площадке (карточка есть, файла может не быть).
builds int Проектов с реально загруженным билдом.
builds_approved int Из них прошли модерацию и допущены к голосованию.
solo / by_teams int Билды в одиночку / командами. В сумме дают builds.
devs_finished int Людей за сданными билдами: соло-авторы плюс все члены команд. 
"overview": {
  "participants": 571,
  "teams_created": 118,
  "projects": 85,
  "builds": 81,
  "builds_approved": 74,
  "solo": 44,
  "by_teams": 37,
  "devs_finished": 173
}

section=builds

Вес билдов. Учитываются вместе zip-архивы и deplex-сборки, по последней версии каждого проекта.

"builds": {
  "count": 81,
  "by_kind": { "zip": 76, "deplex": 5 },
  "bytes_total":  47587189188,
  "bytes_min":       20994563,
  "bytes_max":    13397341394,
  "bytes_median":   194892218,
  "buckets": {
    "lt_100mb":  27,
    "100_300mb": 22,
    "300mb_1gb": 23,
    "gt_1gb":     9
  }
}
Гигабайты бывают разные bytes_total: 47587189188 — это 44,3 ГиБ (делите на 1024³) или 47,6 ГБ в десятичных. В карточках статистики Dustore используется первый вариант.

section=activity

Динамика голосования и скачиваний по дням. Без разбивки по играм — по этой секции нельзя восстановить расстановку мест, поэтому она открыта и во время голосования.

Поле Тип Значение
votes_total int Голосов отдано всего.
voters_total int Уникальных голосующих.
games_with_votes int Работ, за которые есть хотя бы один голос.
downloads_total int Скачиваний билдов джема.
downloaders_total int Уникальных скачавших.
votes_by_day {"YYYY-MM-DD": {votes, voters}} Голоса по дням.
downloads_by_day {"YYYY-MM-DD": int} Скачивания по дням. 
"activity": {
  "votes_total": 1284,
  "voters_total": 312,
  "games_with_votes": 68,
  "downloads_total": 1907,
  "downloaders_total": 349,
  "votes_by_day": {
    "2026-08-14": { "votes": 480, "voters": 121 },
    "2026-08-15": { "votes": 371, "voters":  98 }
  },
  "downloads_by_day": { "2026-08-14": 612, "2026-08-15": 455 }
}
Скачивание = право голоса В джеме действует правило play-to-vote: проголосовать за работу можно только после её скачивания. Поэтому downloaders_total — это верхняя граница для voters_total, а разрыв между ними показывает, сколько людей скачали, но не проголосовали.

section=leaderboard

Закрыт до конца голосования Пока идёт голосование, API отдаёт только объём активности — без очков и мест. Это защита от накрутки: живой рейтинг позволяет целиться в конкретный отрыв. После voting_end секция открывается автоматически.
// во время голосования
"leaderboard": {
  "available_after": "2026-09-14 12:00:00",
  "votes_cast": 1284,
  "voters": 312
}

// после закрытия
"leaderboard": {
  "top": [
    { "place": 1, "id": 231, "name": "КОНТУР",
      "points": 418, "points_weighted": 418.00, "votes": 96 }
  ]
}

Ошибки

Код Тело Когда
404 {"success":false,"error":"Джем не найден"} Нет джема с таким id.
405 {"success":false,"error":"Только GET"} POST, PUT и прочее.
500 {"success":false,"error":"БД недоступна"} Проблема на стороне платформы.

Успешный ответ всегда содержит "success": true. Проверяйте именно это поле, а не только HTTP-код.

Методология

Цифры считаются не так, как можно интуитивно ожидать — вот точные определения, чтобы ваши выводы совпадали с нашими.

  • Момент загрузки билда. Отдельного лога загрузок нет. Для zip берётся время запуска антивирус-скана (он стартует при заливке), для deplex — время последнего committed-билда. Следствие: если проект перезаливали, в статистике видна только финальная версия.
  • Вес билда. Всегда последняя версия. У deplex-проектов в хранилище может лежать больше данных, чем весит финальная сборка, — старые чанки не удаляются.
  • Соло или команда. По фактическому составу команды на момент запроса, а не по галочке, которую участник поставил при регистрации: эти данные расходятся примерно у каждого пятого. Команда из одного человека считается соло.
  • Города. Свободный текстовый ввод. Варианты написания, транслит и опечатки объединяются, мусорные ответы и названия регионов отбрасываются. Сырое число уникальных строк было бы завышено примерно на треть.
  • Движки. Самодекларация из анкеты прогресса, заполняет её меньшая часть участников. Сумма по движкам не равна числу билдов.
  • Скачивания. Считаются на сервере в момент выдачи файла — по zip-загрузкам, deplex-установщику и запуску веб-билда. Открытие страницы игры скачиванием не считается.
  • Очки в лидерборде. points — сырая сумма, points_weighted — с учётом веса голоса (jam_votes.weight); голоса экспертов могут иметь вес, отличный от единицы. Сортировка идёт по взвешенным очкам.

Чего в API нет и не будет

  • Персональных данных: имён, email, телеграмов, ссылок и городов в разрезе конкретных людей.
  • Поимённых голосов и того, кто за что голосовал.
  • Прямых ссылок на файлы билдов — они выдаются только через страницу игры.
  • Контактов разработчиков — это внутренняя информация модерации.

Нужна цифра, которой здесь нет, — напишите, добавим секцию, если её можно отдать обезличенно.
